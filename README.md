# GuildSync

GuildSync is a Windows desktop application for backing up, cloning and synchronizing Discord server structures through the official Discord Bot API.

> Current development release: **0.8.1 alpha**

## What it does

- creates versioned backups of Discord community structures;
- restores or clones supported roles, categories, channels, permissions and emojis;
- offers distinct Safe, Merge and Exact operation modes;
- analyzes destination permissions and bot-role hierarchy before enabling execution;
- records every resource operation in a persistent checkpoint;
- can cancel and resume incomplete operations without blindly repeating completed work;
- verifies the destination structure after cloning or restoration;
- stores the bot token locally instead of sending it to the GuildSync account API;
- supports central accounts, licenses, licensed-device limits and Mercado Pago checkout;
- links a Discord account through a short-lived one-time code;
- includes administration, audit history and automatic update packages.

GuildSync is intended only for communities that the operator owns or is authorized to manage. It does not use user tokens, self-bots or message-content access.

## Reliability model in 0.8

GuildSync 0.8 replaces cross-server ID matching with logical resource keys. Channels are matched by type, normalized name and category path rather than by source `parent_id`, because Discord IDs cannot match across two different servers.

Every operation produces a report in `%LOCALAPPDATA%/GuildSync/Operations` containing:

- operation status and timestamps;
- source and destination identities;
- one checkpoint per resource;
- created/reused target mappings;
- warnings and safe error summaries;
- post-operation verification differences;
- enough state to resume failed or cancelled work.

Backups use format v2 with separate `manifest.json` and `snapshot.json` entries, SHA-256 integrity validation, archive safety limits and compatibility with backups generated by 0.7.

## Components

| Component | Technology | Responsibility |
|---|---|---|
| Desktop | .NET 10 / WPF | Interface, preflight, backup, clone, restore, checkpoints and local bot-token handling |
| Central API | ASP.NET Core / .NET 10 | Accounts, sessions, licenses, licensed devices, payments, audit and Discord linking |
| Discord bot | Discord.Net / .NET 10 | Slash commands for linking, license status and checkout |
| Persistence | PostgreSQL or protected local JSON | Central state and local-development fallback |
| Installer | Inno Setup | Per-user Windows installation and upgrade compatibility |

The executable remains internally named `ClonarDC.exe` and keeps the existing installer application ID so previous installations upgrade instead of becoming a second application. Product-facing names, icons and installer entries use **GuildSync**.

## Security model

- passwords are stored as PBKDF2 hashes with individual random salts;
- access tokens are random, stored only as SHA-256 hashes and expire automatically;
- suspended or revoked accounts lose active sessions immediately;
- login and registration use sliding-window rate limits;
- a device identity is random, protected by Windows DPAPI and stored by the server only as a hash;
- removing a licensed device invalidates sessions associated with it;
- bot-to-API requests require a separate secret with fixed-time comparison;
- payment webhooks are signed and confirmed through Mercado Pago before activating a license;
- production refuses accidental file storage unless it is explicitly enabled;
- PostgreSQL writes use optimistic revision checks to prevent silent overwrites by multiple API instances;
- backup ZIP entries and decompressed sizes are bounded before parsing;
- pull requests scan source contracts and likely committed secrets.

See [SECURITY.md](SECURITY.md) and [docs/production-readiness.md](docs/production-readiness.md).

## Device rollout

The 0.8 API supports device registration immediately. During migration, keep `GUILDSYNC_REQUIRE_DEVICE_ID=false` so existing 0.7 clients can still sign in. After 0.8 is broadly distributed or made mandatory, set it to `true`; logins without a protected device identity will then be rejected.

## Local build

Requirements:

- .NET SDK 10;
- Windows for building and running the WPF desktop;
- Inno Setup 6 for generating the installer.

```powershell
dotnet restore .\src\ClonarDC.Desktop\ClonarDC.Desktop.csproj
dotnet restore .\src\ClonarDC.Server\ClonarDC.Server.csproj
dotnet restore .\src\GuildSync.Bot\GuildSync.Bot.csproj

dotnet build .\src\ClonarDC.Desktop\ClonarDC.Desktop.csproj -c Release
dotnet build .\src\ClonarDC.Server\ClonarDC.Server.csproj -c Release
dotnet build .\src\GuildSync.Bot\GuildSync.Bot.csproj -c Release
```

Copy `.env.example` values into the hosting provider's secret manager. Never commit real tokens, passwords or webhook secrets.

## Deployment

The repository includes:

- `Dockerfile` for the central API;
- `Dockerfile.bot` for the Discord bot;
- `render.yaml` for the API and PostgreSQL staging environment;
- `docs/discord-bot-setup.md` for secure bot configuration;
- `scripts/Test-GuildSyncApi.ps1` for account, session and device behavior tests;
- `scripts/Test-EngineReliability.ps1` for stable-key, backup-v2 and checkpoint tests.

The public API URL currently remains `https://clonar-dc-api.onrender.com` for backward compatibility. A future custom domain can replace it without rebuilding the desktop by updating `api-url.txt`, the current-user registry value or `GUILDSYNC_API`.

## Validation

Pull requests build all three projects and test:

- source contracts and likely committed secrets;
- stable channel keys across different server IDs;
- backup v2 creation, loading and integrity;
- persistent resumable operation reports;
- API startup and 0.8 version;
- registration and mandatory-device policy;
- idempotent device claims and licensed-device limits;
- immediate session invalidation after device revocation;
- logout and administrative suspension;
- rejection of unauthenticated bot requests.

The main-branch release additionally publishes self-contained Windows components, starts the desktop, builds and silently installs the installer, and verifies the automatic-update package hash.

## Current limits

- The central logical state is still one revisioned JSON document in PostgreSQL, so only one API writer should run until storage is normalized.
- Discord forum/media tags, onboarding, automod, messages, members and integrations are not part of the 0.8 structural snapshot.
- Member-specific channel overwrites are reported but not automatically transferred because member IDs are not portable between unrelated servers.
- Code signing, broad external security review and production payment tests remain release-gate items.

## Status

GuildSync 0.8 is an alpha reliability release. It is suitable for controlled testing in disposable servers, but the public paid launch remains blocked by the critical unchecked items in [docs/production-readiness.md](docs/production-readiness.md).
