# GuildSync 0.8.3.3 — Provider Separation Release

## Purpose

This release completes the recovery work by separating the application interface from Discord data access. It does not enable restrictive token-type validation.

## Token behavior

- accepts any text;
- preserves the exact text for the active session;
- saves and reloads the exact text when Remember Token is enabled;
- performs no type, prefix, length or format classification in the interface;
- never silently deletes a value;
- resets the provider state whenever the value changes;
- shows all errors inside the interface.

## Providers

- `DiscordProviderCoordinator` controls provider selection;
- `SimulatedDiscordDataProvider` supplies a complete consistent environment;
- `DiscordService` remains the official provider and uses bot authorization only;
- `RuntimeTokenPolicy` provides a future runtime switch, disabled in this release.

## Simulated workflow

The simulated provider covers server loading, source/destination selection, roles, channels, emojis, plan generation, progress, cancellation, operation completion and backup restore simulation. No Discord content is read or modified.

## Packaging and validation

- Windows x64 self-contained desktop and backend;
- suspiciously small payload and installer gates;
- source/UI/provider contract tests;
- exact arbitrary-value persistence test;
- engine, API, device and administrator tests;
- unpacked launch test;
- clean installer test;
- installed launch test;
- clean uninstall test;
- portable ZIP, source ZIP, updater, manifest and SHA-256 list;
- permanent GitHub Release with asset verification.

## Honest limitations

The CI validates handlers, provider-independent flows and process startup. It does not claim a real destructive Discord operation was run against production communities. Real Discord changes remain dependent on an authorized bot connection, permissions and disposable-server field testing.
